# Small exercise pacing

Small problems are solved twice in the 60-minute segment.

| Block | Minutes |
| --- | --- |
| Approach A | ~25 |
| Approach B | ~25 |
| Comparison | ~10 |

## Keep requirements identical

Both attempts use the same prompt and acceptance criteria. Change exactly one dimension between them:

- A broad initial request versus staged collaboration (requirements, then API, then UI).
- A single agent versus divided work (for example, API and UI handled separately).

Changing more than one dimension makes the comparison unreadable.

## Reset between attempts

Start approach B from the same starter app and seed data. Do not carry over code from approach A.

## Running short

If approach A overruns, shorten approach B to the acceptance criteria that approach A failed or skipped, and keep the full 10 minutes for comparison. The comparison is the teaching moment.
